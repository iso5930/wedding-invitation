# 모바일 청첩장 레이아웃·인터랙션 기획서 v1

작성일: 2026-10-26  
대상: React + TypeScript + Vite 기반 모바일 청첩장 / GitHub Pages  
문서 범위: 화면 구조, 버튼 배치, 이동 경로, 전환 애니메이션, 상태와 예외 처리

## 1. 기획 기준

- 차분한 청첩장 레이아웃을 기본으로 한다. 게임 감성의 시각 표현은 이후 이미지·서체·작은 장식 단계에서 정한다.
- 한 페이지 안에서 세로로 읽는 구조를 사용한다. 섹션 이동 버튼은 같은 페이지의 해당 위치로 이동한다.
- 전체 메뉴, 연락처, 사진 확대는 현재 페이지 위에 겹쳐 여는 팝업으로 구성한다.
- 날짜·시간·장소는 첫 화면에서 확인할 수 있게 한다. 예식 정보 확인에 별도 입장 절차가 필요하지 않다.
- 이번 설계에는 이미지 제작, 배경음악, 영상, 캐릭터 연출을 포함하지 않는다.
- 이름·예식 시간·장소·사진·연락처·계좌는 확정된 내용을 전달받아 입력한다. 현재 날짜 기준값은 2027년 2월 14일이다.
- ‘참석 여부’와 ‘방명록’은 저장 서비스가 필요한 후속 기능으로 구분한다. 기본 버전에는 응답 수집 기능을 넣지 않는다.

## 2. 페이지 구성과 정보 우선순위

| 순서 | 영역 | 주요 정보 | 주요 동작 | 이동 주소 |
|---|---|---|---|---|
| 공통 | 상단 헤더 | 작은 이름 표시, 메뉴 버튼 | 처음으로 이동 / 전체 메뉴 열기 | 모든 영역에서 유지 |
| 1 | 첫 화면 | 초대 제목, 두 사람 이름, 날짜·시간·장소 | 초대장 보기 / 오시는 길 | `#home` |
| 2 | 초대의 글 | 인사말, 가족 소개 | 연락하기 | `#invitation` |
| 3 | 예식 안내 | 날짜·시간, 예식장·홀, 달력, 남은 날짜 | 오시는 길 | `#ceremony` |
| 4 | 사진첩 | 대표 사진, 전체 사진 | 더 보기 / 사진 확대 | `#gallery` |
| 5 | 오시는 길 | 장소·주소, 지도 앱, 교통·주차 | 주소 복사 / 지도 열기 / 안내 펼치기 | `#location` |
| 6 | 마음 전하기 | 신랑 측·신부 측 계좌 | 계좌 펼치기 / 복사 | `#gift` |
| 7 | 마지막 인사 | 감사 문구 | 링크 복사 / 맨 위로 | `#closing` |

핵심 정보의 우선순위는 ‘일시·장소 → 초대의 글 → 이동 안내 → 사진·부가 정보’다. 오시는 길은 본문 순서와 관계없이 첫 화면과 전체 메뉴에서 바로 접근할 수 있다.

## 3. 공통 레이아웃 규칙

### 3.1 크기와 여백

- 모바일 기준 너비: 390px. 320px에서도 가로 스크롤 없이 동작해야 한다.
- 본문 최대 너비: 480px. 넓은 화면에서는 중앙 정렬한다.
- 좌우 여백: 기본 24px, 360px 미만에서는 20px.
- 섹션 위아래 여백: 기본 64px. 제목과 본문 간격 24px, 관련 버튼 간격 12px.
- 본문 글자: 기본 16px, 줄 높이 약 1.7. 보조 정보는 14px 이상.
- 주요 버튼 높이: 48px 이상. 아이콘 버튼도 실제 터치 영역은 최소 44×44px.
- 긴 이름·주소는 자연스럽게 줄바꿈한다. 고정 높이로 내용을 자르지 않는다.
- 첫 영역은 모바일 화면 높이에 맞는 여백을 주되, 작은 화면이나 큰 글자 설정에서는 콘텐츠 높이만큼 늘어난다.

### 3.2 상단 헤더

```text
┌──────────────────────────────────┐
│ [신랑 · 신부]            [메뉴]  │  높이 56px + 상단 안전 여백
└──────────────────────────────────┘
```

- 왼쪽 이름은 `#home`으로 이동하는 텍스트 버튼이다.
- 오른쪽 ‘메뉴’는 전체 메뉴 바텀시트를 연다.
- 헤더는 스크롤 중에도 상단에 유지한다. 배경은 본문을 가리지 않는 단색으로 한다.
- 섹션 이동 시 제목이 헤더 뒤에 가려지지 않도록 ‘헤더 높이 + 16px’를 남긴다.
- 하단 고정 탭바는 두지 않는다. 주요 이동은 헤더의 메뉴와 본문 버튼으로 제공한다.

## 4. 영역별 설계도

아래 도식은 콘텐츠의 배치 순서를 뜻한다. 이미지 크기·형태·장식은 후속 시각 디자인 단계에서 정한다. 이번 문서의 첫 화면은 이미지 없이도 성립하는 텍스트·버튼 구조다.

### 4.1 첫 화면 — `#home`

```text
┌──────────────────────────────────┐
│ 신랑 · 신부                 메뉴 │
├──────────────────────────────────┤
│                                  │
│         WEDDING INVITATION        │
│                                  │
│               우리,              │
│           결혼합니다.            │
│                                  │
│            신랑 · 신부           │
│                                  │
│            2027.02.14            │
│            일요일 · 시간         │
│            예식장 · 홀           │
│                                  │
│ 같은 곳을 바라보며,              │
│ 함께 걸어가겠습니다.             │
│                                  │
│     [      초대장 보기      ]     │
│                                  │
│              오시는 길 →         │
│                                  │
└──────────────────────────────────┘
```

- 텍스트는 중앙 정렬한다. 버튼 그룹은 예식 정보와 소개 문구 아래에 배치한다.
- ‘초대장 보기’: 본문 너비를 사용하는 주요 버튼. `#invitation`으로 이동한다.
- ‘오시는 길’: 주요 버튼 아래 16px 간격의 텍스트 버튼. `#location`으로 바로 이동한다. 실제 터치 영역은 충분히 확보한다.
- 미확정 시간·장소는 확인되지 않은 값으로 채우지 않는다. 기획·미리보기 단계에서는 ‘시간 안내 예정’, ‘장소 안내 예정’으로 표시한다.
- 첫 화면 전체를 닫거나 사라지게 하지 않는다. 아래로 스크롤하면 자연스럽게 다음 영역이 이어진다.

### 4.2 초대의 글 — `#invitation`

```text
[작은 영역 제목: 초대의 글]

두 사람의 새로운 시작

인사말 본문
4~8줄, 문단 사이 충분한 여백

신랑 측 가족 소개
신부 측 가족 소개

[             연락하기             ]
```

- ‘연락하기’는 연락처 바텀시트를 연다. 버튼을 누르자마자 전화를 연결하지 않는다.
- 바텀시트의 첫 줄에는 신랑·신부, 필요 시 아래에 양가 연락처를 배치한다.
- 각 사람마다 이름과 ‘전화’, ‘문자’ 버튼을 따로 둔다.
- ‘전화’는 기기의 전화 앱, ‘문자’는 문자 앱을 연다. 사용자가 앱에서 최종 실행한다.
- 등록되지 않은 사람이나 연락처는 표시하지 않는다.

### 4.3 예식 안내 — `#ceremony`

```text
예식 안내

2027년 2월 14일 일요일
예식 시간
예식장 이름 · 홀

[              달력               ]
          예식 날짜에 표시

함께할 날까지 D-000

[             오시는 길            ]
```

- 날짜·시간·장소를 달력보다 먼저 배치한다.
- 달력은 읽기용 정보이며 눌러야 할 UI처럼 표현하지 않는다.
- 남은 날짜는 한국 시간의 날짜를 기준으로 계산한다. 당일은 ‘오늘, 함께하는 날’, 이후는 감사 문구로 전환한다.
- ‘오시는 길’은 `#location`으로 이동한다.

### 4.4 사진첩 — `#gallery`

```text
우리의 순간들

[ 사진 1 ] [ 사진 2 ]
[ 사진 3 ] [ 사진 4 ]
[ 사진 5 ] [ 사진 6 ]

[             사진 더 보기          ]
```

- 기본 노출은 최대 6장, 2열 배치다. 실제 사진 수가 적으면 있는 사진만 표시한다.
- 사진이 6장을 넘을 때만 ‘사진 더 보기’를 표시한다.
- ‘사진 더 보기’는 같은 영역 안에서 나머지를 펼치고 ‘접기’로 바뀐다.
- 사진을 누르면 해당 사진의 전체 화면 뷰어를 연다. 확대용 화면이므로 이 문서에서는 사진 내용 자체를 설계하지 않는다.
- 뷰어: 상단 ‘현재 번호 / 전체 장수’, 오른쪽 ‘닫기’, 중앙 사진, 좌우 이동 버튼.
- 모바일은 좌우 스와이프, 키보드는 좌우 방향키로 이전·다음 사진을 볼 수 있다.
- 첫 사진에서 이전, 마지막 사진에서 다음 버튼은 비활성화한다. 무한 순환하지 않는다.
- 닫으면 눌렀던 사진의 스크롤 위치와 포커스로 돌아온다.
- ‘접기’로 높이가 줄어들 때는 사진첩 제목 위치를 유지해 다른 영역으로 화면이 튀지 않게 한다.

### 4.5 오시는 길 — `#location`

```text
오시는 길

예식장 이름 · 홀
도로명 주소
[             주소 복사             ]

[           실제 위치 안내          ]  후속 지도 표현 영역

[    네이버지도    ] [    카카오맵    ]

[ 대중교통 안내                  ∨ ]
[ 주차 안내                      ∨ ]
[ 셔틀 안내                      ∨ ]
```

- 장소·주소는 지도보다 위에 둔다.
- ‘주소 복사’는 주소 문자열만 복사한다. 성공하면 하단에 ‘주소가 복사되었습니다’를 2초 표시한다.
- ‘네이버지도’와 ‘카카오맵’은 해당 서비스의 예식장 위치·길찾기 링크를 새 탭 또는 해당 앱으로 연다. 실제 이동은 기기 환경에 따른다.
- 유효한 주소·위치 링크가 준비되기 전에는 지도 버튼을 비활성화하고 ‘장소 확정 후 이용 가능합니다’를 표시한다.
- 대중교통·주차·셔틀은 제목을 누르면 내용이 펼쳐지는 아코디언이다. 각 항목은 독립적으로 열 수 있다.
- 제공되지 않는 교통 항목은 숨긴다. 예를 들어 셔틀이 없으면 셔틀 안내도 표시하지 않는다.
- 주소 복사가 실패하면 주소를 선택할 수 있는 안내 창과 ‘주소를 길게 눌러 복사해주세요’를 제공한다.

### 4.6 마음 전하기 — `#gift`

```text
마음 전하기

축하의 마음에 감사드립니다.

[ 신랑 측 계좌                   ∨ ]
  관계 / 예금주
  은행명 · 계좌번호
  [ 계좌번호 복사 ]

[ 신부 측 계좌                   ∨ ]
```

- 두 그룹은 기본적으로 접힌 상태다. 그룹별로 독립적으로 펼칠 수 있다.
- 계좌가 여러 개면 예금주·은행·번호·복사 버튼을 한 묶음으로 반복한다.
- ‘계좌번호 복사’는 계좌번호만 복사하고 ‘계좌번호가 복사되었습니다’를 2초 표시한다.
- 복사 실패 시 해당 번호를 선택할 수 있게 하고 수동 복사를 안내한다.
- 등록된 계좌가 없거나 마음 전하기를 원하지 않으면 영역 전체와 메뉴 항목을 숨긴다.

### 4.7 마지막 인사 — `#closing`

```text
함께해 주셔서 감사합니다.
신랑 · 신부

[            청첩장 링크 복사        ]

               맨 위로 ↑
```

- ‘청첩장 링크 복사’는 팝업 상태·섹션 위치를 제외한 청첩장 기본 주소를 복사한다.
- ‘맨 위로’는 `#home`으로 이동한다.
- 별도의 회원가입·앱 설치 없이 마무리한다.

## 5. 전체 메뉴 바텀시트

```text
┌──────────────────────────────────┐
│                ─                 │
│ 전체 메뉴                   닫기 │
│                                  │
│ 처음                         →   │
│ 초대의 글                    →   │
│ 예식 안내                    →   │
│ 사진첩                       →   │
│ 오시는 길                    →   │
│ 마음 전하기                  →   │
└──────────────────────────────────┘
```

- 헤더 ‘메뉴’를 누르면 아래에서 올라온다. 배경에는 반투명 어두운 막을 표시한다.
- 항목은 한 줄 전체가 터치 영역이며 행 높이는 최소 48px로 한다.
- 현재 보고 있는 영역에만 작은 표시를 준다.
- 항목을 누르면 시트를 먼저 닫고 해당 섹션으로 이동한다. 닫힘과 스크롤을 동시에 실행하지 않는다.
- 항목 선택 → 닫힘 220ms → 스크롤 450ms, 총 약 670ms를 기준으로 한다.
- 닫기 버튼·배경·Esc·모바일 브라우저 뒤로가기로 닫을 수 있다.
- 바텀시트 내용이 길면 내부만 스크롤하며 높이는 화면의 80%를 넘지 않는다.
- 처음 구현에서는 드래그로 닫는 제스처를 넣지 않는다. 닫기 동작을 명확하게 제공한다.
- 없는 섹션은 메뉴에서도 숨긴다.

## 6. 버튼 및 이동 전체 명세

| 버튼 / 입력 | 위치 | 결과 | 전환 / 종료 |
|---|---|---|---|
| 이름 표시 | 공통 헤더 왼쪽 | `#home` 이동 | 스크롤 450ms |
| 메뉴 | 공통 헤더 오른쪽 | 전체 메뉴 시트 열기 | 아래→위 240ms |
| 메뉴 항목 | 전체 메뉴 | 해당 섹션 이동 | 닫기 220ms → 스크롤 450ms |
| 초대장 보기 | 첫 화면 하단 | `#invitation` 이동 | 스크롤 450ms |
| 오시는 길 | 첫 화면 / 예식 안내 | `#location` 이동 | 스크롤 450ms |
| 연락하기 | 초대의 글 아래 | 연락처 시트 열기 | 아래→위 240ms |
| 전화 / 문자 | 연락처 시트 | 기기 전화·문자 앱 열기 | 앱 전환은 기기 기본 동작 |
| 사진 더 보기 / 접기 | 사진첩 아래 | 같은 영역 확장 / 축소 | 작은 사진 목록은 높이 전환 200ms, 많은 사진은 높이 효과 생략 |
| 사진 | 사진첩 | 전체 화면 사진 뷰어 열기 | 페이드 180ms |
| 좌우 스와이프 / 이전·다음 | 사진 뷰어 | 사진 변경 | 짧은 수평 전환 220ms |
| 뷰어 닫기 | 사진 뷰어 오른쪽 위 | 이전 본문 위치로 복귀 | 페이드 160ms |
| 주소 복사 | 오시는 길 | 주소를 클립보드에 복사 | 토스트 표시 |
| 지도 앱 | 오시는 길 | 등록된 지도 링크 열기 | 외부 서비스 이동 |

| 맨 위로 | 마지막 인사 아래 | `#home` 이동 | 스크롤 450ms |

## 7. 애니메이션 규칙

| 동작 | 기본값 | 세부 규칙 |
|---|---|---|
| 섹션 이동 | 450ms, ease-in-out | 현재 위치에서 목표 제목 위로 이동. 사용자 스크롤이 시작되면 자동 이동 중단. 이동 중 다른 목적지를 누르면 마지막 목적지로 갱신 |
| 버튼 누름 | 100ms | 배경색만 약하게 변경. 확대·튀어 오름 효과 없이 클릭 반응 제공 |
| 바텀시트 열기 | 240ms, ease-out | 아래에서 최종 위치까지 이동. 배경 막은 180ms 페이드 |
| 바텀시트 닫기 | 220ms, ease-in | 아래로 이동. 배경 막 함께 사라짐 |
| 사진 뷰어 | 열기 180ms / 닫기 160ms | 검정 배경과 화면을 페이드. 사진 자체 과도한 확대 효과는 넣지 않음 |
| 사진 넘기기 | 220ms | 드래그 방향을 따르는 짧은 수평 전환 |
| 아코디언 | 200ms, ease-out | 내용 높이와 화살표 방향만 변경 |
| 토스트 | 표시·숨김 120ms / 유지 2초 | 화면 하단 안전 여백 위에 표시. 연속 복사 시 최근 메시지로 교체 |
| 본문 읽기 | 별도 등장 효과 없음 | 스크롤만으로 텍스트가 숨겨지거나 등장 대기 상태가 되지 않음 |

- 팝업이 열려 있는 동안 배경 페이지 스크롤을 고정한다.
- ‘움직임 줄이기’ 설정에서는 섹션 이동·시트 이동·아코디언·사진 슬라이드를 즉시 전환하고, 필요한 페이드는 100ms 이내로 제한한다.
- 길게 이어지는 연출이나 자동으로 반복되는 UI 움직임은 기본 버전에 넣지 않는다.
- 전환 시간은 구현 후 실제 기기에서 확인하고, 답답하게 느껴지면 줄인다.

## 8. 주소·뒤로가기·포커스 규칙

- 섹션 이동은 주소의 해시(`#location` 등)를 갱신한다. 해당 주소를 직접 열어도 그 섹션을 볼 수 있어야 한다.
- 직접 링크로 들어온 첫 로딩에서는 이동 애니메이션 없이 목표 섹션을 정렬한다.
- 메뉴·연락처·사진 뷰어를 열면 임시 탐색 상태를 하나 추가한다. 뒤로가기는 팝업만 닫고 페이지를 떠나지 않도록 한다.
- 닫기 버튼으로 닫을 때는 임시 상태도 함께 정리해 ‘뒤로가기를 두 번 눌러야 하는 현상’을 막는다.
- 전체 메뉴에서 섹션을 선택할 때는 팝업 임시 상태를 제거한 다음 섹션 이동 기록을 남긴다.
- 팝업을 열면 포커스가 내부로 이동하고, Tab 키는 팝업 내부에서 순환한다.
- 팝업을 닫으면 열었던 버튼으로 포커스를 돌린다. 메뉴로 섹션 이동을 선택한 경우에는 목적지 제목으로 포커스를 이동한다.
- 일반 섹션 이동도 도착한 제목을 읽을 수 있도록 포커스를 맞춘다.
- `#gift`처럼 숨겨진 섹션 주소로 들어오면 첫 화면으로 이동한다.

## 9. 상태와 예외 처리

| 상황 | 표시와 처리 |
|---|---|
| 시간·장소 미확정 | 안내 예정 문구. 실제 정보처럼 보이는 가상 값은 사용하지 않음 |
| 연락처 없음 | 연락하기 버튼 또는 해당 사람 항목 숨김 |
| 사진 없음 | 사진첩 영역과 전체 메뉴 항목 숨김 |
| 사진 로딩 중 | 기존 배치 크기를 유지하는 단색 자리 표시 |
| 사진 로딩 실패 | ‘사진을 불러오지 못했습니다’와 ‘다시 시도’ 버튼 |
| 계좌 없음 | 마음 전하기 영역과 전체 메뉴 항목 숨김 |
| 교통 항목 없음 | 해당 아코디언 숨김 |
| 지도 링크 없음 | 비활성화하고 이유를 짧게 표시 |
| 클립보드 복사 실패 | 선택 가능한 텍스트와 수동 복사 안내 |
| 작은 화면·큰 글자 | 자연스러운 줄바꿈과 본문 확장. 버튼·제목 잘림 방지 |
| 외부 지도에서 돌아옴 | 본문 위치를 유지 |

## 10. 구현 순서

1. 이미지 없는 회색 와이어프레임으로 전체 섹션·텍스트·버튼 배치를 만든다.
2. 해시 이동, 전체 메뉴, 연락처 시트, 아코디언, 복사 동작을 연결한다.
3. 사진 뷰어와 팝업 뒤로가기·포커스·스크롤 복원 동작을 연결한다.
4. 모바일에서 배치와 전환 속도를 검토한다.
5. 구조가 정리된 뒤 서체·색상·픽셀 요소·실제 이미지를 적용한다.
6. 확정 정보를 입력하고 GitHub Pages에서 실제 동작을 확인한다.

이번 기획서 작성 단계에서는 기존 배포 사이트를 변경하지 않는다. 다음 산출물은 위 구조를 눌러볼 수 있는 이미지 없는 와이어프레임이다.

## 11. 확인 기준

- 첫 화면에서 날짜·시간·장소 및 주요 버튼이 명확하게 구분된다.
- 첫 화면에서 오시는 길까지 한 번의 버튼 입력으로 이동한다.
- 섹션 제목이 고정 헤더에 가려지지 않는다.
- 전체 메뉴, 연락처, 사진 뷰어는 닫기와 모바일 뒤로가기로 종료된다.
- 팝업을 닫아도 본문 위치가 달라지지 않는다.
- 안내 항목을 펼쳐도 현재 읽던 제목 위치가 크게 바뀌지 않는다.
- 성공한 복사에만 성공 토스트가 나타난다.
- 미확정 정보와 준비되지 않은 링크의 상태가 분명하다.
- 320px·390px·430px 너비에서 가로 넘침이 없고, 버튼을 누르기 쉽다.
- 움직임 줄이기 설정과 키보드 조작으로도 주요 기능을 사용할 수 있다.
